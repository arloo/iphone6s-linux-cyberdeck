# Samsung A9 N71: Broadcom BCM4350 PCIe Wi-Fi bring-up blockers

**2026-11-11.** READ-ONLY source analysis and offline integration planning. No Wi-Fi access, PCIe enumeration, MMIO access or RF transmission achieved on this live Linux session.

## Real S8000 hardware evidence

The private Apple ADT was previously analyzed, and its sanitized hardware layout was published in N71_PCIE_ADT_MAPPING.md. It identifies the A9 PCIe host (apcie,s8000), port 1 WLAN (Broadcom BCM4350) and associated dart-apcie1. **Port 0** serves storage-related hardware; **port 2** serves baseband. These ports must remain excluded from experiments. The current live Linux kernel enumerates no PCIe endpoints, no wlan interface and no ieee80211 class.

## Pinned Linux source review

In the pinned HoolockLinux tree powering the already validated touchscreen/GUI RAM boot:

- The Apple host bridge driver (drivers/pci/controller/pcie-apple.c) matches generic apple,pcie with T8103-like register layout and apple,t6020-pcie. It does NOT expose an S8000-specific hardware profile. A generic apple,pcie match does not prove A9 register compatibility.
- Its port initialization modifies APPCLK, PERST#, PHY/reference clocks, RID/SID mappings, interrupts and PCIe link-training registers. Exposing storage/modem ports through the wrong Device Tree would therefore modify critical hardware before WLAN enumeration begins.
- The Apple DART driver (drivers/iommu/apple-dart.c) has several newer-generation matches but no explicit apple,s8000-dart match. The real Apple S8000 ADT also has a legacy dart,s5l8960x compatible; the Linux apple,s5l8960x-dart hardware-family driver exists, but using it on A9 is not yet qualified. See N71_S8000_PCIE_DART_ADT_WINDOW_AUDIT_2026_11_11.md. A9's DMA translation, stream IDs, aperture and fault handling need independent verification.
- The kernel enables PCI and CONFIG_PCIE_APPLE, but CFG80211/BRCMFMAC are not active. Adding Broadcom Wi-Fi firmware or compiling the network module alone cannot establish the missing PCIe host link.

## Safety gates

1. OFFLINE: derive an A9 S8000 register-layout/compatible profile from supported open code and the sanitized ADT. Verify clock, power, IRQ and MMIO register meanings without writing unknown registers.
2. Port isolation: a prototype DT must expose ONLY WLAN port 1. Storage port 0 and baseband port 2 remain disabled. Verify that global controller initialization cannot implicitly modify those excluded ports. Reject any unisolated probe.
3. DART/IOMMU: establish validated port-1 stream IDs and DMA translation before enabling any PCIe bus master. Do not disable address protection or allow unrestricted DMA.
4. Driver profile: use an explicitly separate A9 match, not T8103 register offsets guessed compatible with A9. Keep experiment opt-in and disabled by default.
5. Controlled supervised test: new private RAM-only image only, keeping known-good autoinit touch+GUI payload as fallback. Verify shell and USB first. Abort on faults or unexplained USB loss and do not loop link resets.
6. After safe BCM4350 enumeration: add cfg80211/brcmfmac PCIe kernel support and use correctly licensed board-matched firmware/NVRAM privately. Check connectivity only against an operator-authorized wireless AP.
7. Bluetooth independently requires correct UART/power/coexistence mapping; built-in HCI UART/Broadcom source does not prove any active HCI controller.

## Immediate next work

A source-based S8000-specific port-1 PCIe/DART compatibility prototype and automated isolation checks, completed offline before any risky live register operations. The active iPhone remains on the successful Linux GUI+touch RAM boot.
