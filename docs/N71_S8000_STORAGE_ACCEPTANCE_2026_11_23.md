## 2026-11-23 additional original Apple request-pool factory trace

The owner-private, exact-hash-gated `IONVMeFamily` 2.1.0 source now confirms a further direct call chain in the constructor/factory: **three alternative top-level pool wrappers forward their incoming `x4` as `x5`**, the underlying pool constructor stores that argument, and a pool helper computes a conditional mask (`w25 &= w24`) before forwarding the resulting value to the per-request allocator. That allocator passes it as factory `w5`; the factory passes it as initializer `x6`. The initializer sets internal request flag bit3 iff `x6` is nonzero; the original Read builder then maps that flag into **CDW0 bit13** (second command byte `BIT(5)`). This is now covered by **79 instruction fingerprints and 17 exact `BL` targets**, verified against the full authentic original executable SHA-256 and synthetic mutation cases.

The next source step identifies a **common source for all three wrapper `x4` values**: the output of a controller virtual method at vtable offset **1440**. The original initializer branches between the three wrappers, but each forwards the returned value in `x22` as `x4`. This further narrows the live uncertainty to the selected controller implementation, its method return and the pool's `w24` mask. The traced data flow **does not establish the live N71's virtual-method return, filter result, or final `BIT(5)` setting**. In particular, class/vtable reachability from an original prelinked driver does not demonstrate that Apple's N71 runtime takes that path. The stage remains **original-source evidence only**, with no physical S3E queue creation, NAND reads/writes or DMA lifetime changes. The only active module on the phone remains the bounded charging supervisor, when its lease is valid.

## 2026-11-23 original Apple request-pool boolean mask — all 8 cases proven offline

The authenticated `IONVMeFamily` `AppleNVMeRequestPool` helper at original executable offset `0x229f0` first preserves the controller-derived flag in `w25`, and an independent auxiliary argument `x5` in `x20`. The original code calls the predicate helper at `0x3031c`, which returns **0 or 1** based on an object lookup; then it computes `w8=(x20 != 0)`, `w24=predicate_result | w8`, and **`w25 &= w24`** before forwarding the masked flag to the per-request allocator. The original initializer maps bit0 of this argument to internal request bit3, which the Read builder maps to CDW0 bit13 (second command byte `BIT(5)`). The verified *boolean bit0* is therefore **`controller_bit AND (lookup_predicate OR auxiliary_nonzero)`**. A new whole-original-executable-hash-gated source audit independently checks the actual AArch64 mask, its predicate helper, the two BL call targets and all 8 modeled input combinations. Tool: `tools/n71_s8000_original_read_flag_mask_gate.py`; tests: `tests/test_n71_s8000_original_read_flag_mask_gate.py`.

**Important:** Even if the matching AppleEmbedded controller method would return `1`, this **does not guarantee** CDW0 `BIT(5)` because the lookup and auxiliary values still condition the flag. The source gate does not establish the active iOS controller instance, predicate value, auxiliary argument, actual request transfer, PRP-to-FlatDMA tag1 mapping, nor DMA retirement. The first physical NAND read remains **unperformed and unauthorized** while these safety gates and battery recovery are pending.

## 2026-11-24 Read/Write direction correction and original selector semantics

Original main kernel symbol-table resolution of seven concrete memory-descriptor vtables (including IOMemoryDescriptor, IOGeneralMemoryDescriptor and IOBufferMemoryDescriptor) identifies virtual slot 168, relative to the vtable address point, as IOMemoryDescriptor::getDirection() const. The original IONVMeFamily handler calls this slot at 0x12df8 and validates values 1 and 2; at 0x13240 selector 2 falls through to the wrapper at 0x365b4, whose builder emits WRITE opcode 1, while selector 1 branches to the wrapper at 0x36390, whose builder emits READ opcode 2. This corrects the previously reversed branch annotations without changing the original call addresses or the common IOVM mapping path. The original AppleS800xPCIe FlatDMA direction path obtains the same virtual slot and maps 1 to 0x200 and 2 to 0x100. Apple public IOMemoryDescriptor definitions independently agree (kIODirectionIn=1, kIODirectionOut=2). The existing inert candidate uses 0x200, consistent with Read direction; no descriptor or hardware programming was changed. Original-source gate now checks 90 instruction fingerprints and 19 call targets; five tests pass. This does not establish that the original N71 runtime binds this FlatDMA mapper for Read, its physical mapping, completion or DMA lifetime.
