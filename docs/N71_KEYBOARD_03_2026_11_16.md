# Native portrait keyboard 0.3 — 2026-11-16

The owner confirmed that the initial touch console worked, but reported small, uncomfortable keys. This revision replaces the compact six-row keyboard with a portrait-phone QWERTY arrangement, inspired by the familiar iPhone layout. It is the project's own framebuffer implementation, not Apple's keyboard software.

| Element | Previous UI | Revision 0.3 |
|---|---|---|
| Alphabet | Number row plus three compact character rows | Three QWERTY rows, staggered |
| Ordinary visible key | 64 × 60 pixels | 69 × 108 pixels |
| First-row touch cell | Gaps between compact buttons | Full 75 × 116 pixel cells across the screen |
| Letter glyph | Scale 1 | Scale 2, twice the raster height/width |
| Shift/delete | Small shared control strip | Dedicated sides of the third row; conventional icons |
| Space | 134-pixel shared control | 354-pixel bottom-row key |
| Numbers/symbols | Separate small symbol control | 123, #+= and ABC modes |
| Return | Shared small control | Dedicated bottom-right INVIO key |
| Terminal view | 48 × 24 characters | 48 × 20, leaving room for taller keys |

The second alphabet row is centered; the third is framed by Shift and Delete. Drawing and touch hit-testing use one shared geometry table. Horizontal gaps/row margins resolve to the nearest key in that row. The extra Ctrl-C, Tab and Clear View controls sit above the keyboard. Shift returns to lowercase after one letter, and number/symbol mode does not consume an extra permanent row.

## Checks performed

- Warning-clean static ARM64 compilation and host ASan/UBSan checks.
- Existing actual-PTY command test updated for the new layout and passed on host and phone.
- Explicit Q/P/A/Delete mapping, alphabet/number/symbol transitions, one-shot Shift and complete row hit coverage checked in the native selftest.
- Updated executable hash verified before replacing the running app; new UI starts directly in Terminal.
- Actual phone framebuffer readback reviewed. WLAN remained WPA_COMPLETED; no radio or charging settings were changed by the keyboard deployment.

The owner's confirmation applies to revision 0.2 functionality; comfort/accuracy of revision 0.3 still needs the next manual trial. No automatic touch injection or synthetic key dispatch is presented as a real finger test.

A fresh owner-private integrated RAM candidate is also rebuilt with this executable. The earlier candidate/recovery images are retained. The new candidate has not been transferred through Pongo or physically booted; it needs the same supervised new-boot acceptance.
