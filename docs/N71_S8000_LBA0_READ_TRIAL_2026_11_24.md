## Explicit transport choice and remaining Apple-policy uncertainty

The current successful Identify builder explicitly uses command byte1=32 and FlatDMA tag0. The physically accepted queue commands use byte1=0 with direct DART queue IOVAs. These are different transport uses and must not be conflated.

The Read candidate requires separately selected ans_lba0_read_flags=32; no other Read flag is accepted and there is no alternative-flag retry. It reuses the successful Identify's device-to-host TCB/SGL convention with a disjoint descriptor: 128-byte slot1, source-verified 8 MiB tag stride and virtual tag1 at 0x40800000. The source-qualified NVM Read builder supplies the standard opcode/NSID/LBA/NLB fields.

This is a **declared Linux transport hypothesis**, not proof that the original live iOS request factory selects the same flag, mapper or dynamic provider class. The earlier iOS-policy source investigation remains valid and open. Physical completion/data evidence must qualify this NVM-specific use; successful admin Identify or queue creation alone does not.

## Pre-epoch publication and lifetime

ans_lba0_read_once=1 requires Identify, queue creation, explicit queue flags0, empty-queue deletion and explicit Read flags32. Disabled mode requires the Read flag to remain unselected. Invalid combinations are rejected before board/PMGR/hardware setup.

Before the first possible BME epoch, four already allocated independent 16 KiB Linux DMA pages hold I/O SQ, CQ, Read data and Read SGL. Linux-owned CPU shadow TCB/SGL pages are checked against all inherited and currently owned exclusion ranges before being written. All four live I/O preimages must be zero. The pure tag1 stage validates tag0 and slot1; live table preimages are rechecked before publication.

The data frame receives per-boot 64-bit witnesses across 16 KiB; only the first 4 KiB may change. The isolated SGL is synchronized first. Only live TCB slot1 is copied; tag0 and all other slots remain unchanged. Page count is published last, followed by streaming cache synchronization and a bounded source-verified NVMMU+4/bit16 invalidation. Its phase-specific guard allows only invalidate 0/0x10000 while CC/CSTS and both PCI master bits remain off, ownership roots/SART/HMB remain exact and the DMA epoch is still unlatched. It does not call a stable qualifier that would falsely reject the busy bit.

After any published uncertainty, all DMA backing and original driver/power ownership are retained. Only CPU-only shadow pages are freed. No DMA unmap/free, inherited table mutation, active-root replacement or independent DMA-drain claim is introduced.

## Single submission, completion and data witness

Only after the current Identify and both Create completions validate does the Read path run. It refuses foreign/nonzero SQ/CQ slots without erasing them. The complete fixed command is checked before copying to I/O SQ slot0, and the submission latch is set before the one I/O SQ-tail write.

CQ polling is bounded and checks the independent observed/copy status, phase/status 0001, CID1, SQID1 and SQ head1. The CQ head is acknowledged only after validation and a current owned/running-controller check. No second Read is possible.

CQ success is not data proof. Independent streaming-DMA reads of the data frame require every one of 512 sector word witnesses to change, with all 1536 guard words outside the 4096-byte transfer unchanged. A missing payload, guard overrun, foreign completion, timeout or controller failure stops progression. The witness establishes received data in the intended owned frame; it is not cryptographic sector authentication or DMA retirement. Raw bytes, payload hashes and witness seeds are never logged or exported.

Delete SQ/CQ is permitted only after the Read's validated/acknowledged completion and independent data witness prove this single submitted I/O has completed. An uncertain Read does not lead to more queue commands or another flag attempt. The existing controller-stop/BME-off attempt and retained-backing policy remain; a failed trial is not retried in the same boot.
