## Scope and implementation

`endpoint_id_trial=1` requires `observe_p0_config=1`,
`dart0_all_streams=1`, `dart0_owned_roots=1`, late root controls and
the existing NAND reset/power guards. A single finit_module call and
session one-shot marker prevent automatic repeated hardware attempts.

The trial uses the existing bounded local-port helper. It enables local
control0x80, releases GPIO160, observes the link25 times with4ms sleep
requests, then identifies the endpoint before restoring the bus route,
reasserting reset and restoring local0x80. The storage-specific config
helper rejects the WLAN bridge ID, a pre-existing secondary route and
unexpected endpoint bus mastering. It never writes command, BAR or NVMe
registers. A failed route/local/reset rollback requests quarantine that
retains translation tables, pages, power and module ownership.

Host-compiled failure cases check routing restoration, identity mismatch,
bus-master rejection, unavailable routing, lost readiness and retention
after an unsafe observer rollback. These are control-flow tests; the
physical observations above came from the iPhone.

This is direct PCIe config identification, not a registered Linux PCI
device, a bound NVMe driver or a readable namespace. No NVMe command,
filesystem operation or NAND data write was performed. Next: qualify
the controller BAR and read NVMe capability/state registers while
endpoint bus mastering stays disabled, then implement the S3E/NVMe MMU
transport and controlled namespace reads.
